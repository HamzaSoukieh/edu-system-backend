# Academic Profile Postman Guide

This guide covers:

- `postman/academic-profile.postman_collection.json`
- `postman/academic-profile.local.postman_environment.json`

The collection tests the shared academic profile routes added through AP1-AP5 and the AP4 `warnings` / `excluded` response improvements.

## Import And Run

1. Start the backend:

```powershell
npm start
```

2. Import both Postman files:

- Collection: `academic-profile.postman_collection.json`
- Environment: `academic-profile.local.postman_environment.json`

3. Select the `Academic Profile AP1-AP5 Local` environment.

4. Fill the required variables listed below.

5. Run folders in this order:

- `00 Auth And Context`
- `01 Shared Academic Profile - Self Access`
- `02 Shared Academic Profile - Staff Access`
- `03 School Academic Profile Checks`
- `04 University Academic Profile Checks`
- `05 AP4 Excluded Explanation Scenarios`
- `06 Negative And Authorization`

Run the school finalization and override requests only on throwaway data. They use existing write routes and will create/update a real `SchoolFinalOutcome`.

## Required Manual Variables

Fill these before running the main checks:

- `baseUrl`: defaults to `http://localhost:5000`
- `adminEmail`
- `adminPassword`
- `studentEmail`
- `studentPassword`
- `schoolInstitutionId`
- `universityInstitutionId`
- `schoolStudentMembershipId`
- `universityStudentMembershipId`
- `semesterId`

These are optional but useful for negative or specialized checks:

- `otherInstitutionId`
- `schoolOtherStudentMembershipId`
- `universityNoOutcomeInstitutionId`
- `universityNoOutcomeStudentMembershipId`

These may be saved/generated by requests:

- `adminToken`
- `studentToken`
- `adminUserId`
- `studentUserId`
- `activeInstitutionId`
- `academicYearId`
- `schoolFinalOutcomeId`

The collection generates `academicYearId` if it is blank.

## AcademicYear Note

There is no `AcademicYear` model or API route yet. Do not create an AcademicYear request for this flow.

School academic profiles currently require the caller to pass `academicYearId` explicitly. Use a generated ObjectId-like value for local testing, and make sure your school policies/report cards/final outcomes use the same value. A real AcademicYear/current-year resolver is a later task.

## What Frontend Should Verify

All shared academic profile responses use:

```json
{
  "academicProfile": {
    "institutionType": "school",
    "student": {},
    "summary": {},
    "warnings": [],
    "excluded": []
  }
}
```

`institutionType` is either:

- `school`
- `university`

School profiles can additionally include:

- `academicYear`
- `reportCards.yearly`
- `reportCards.semester`
- `finalOutcome`

University profiles can additionally include:

- `semesters`
- `subjectAttempts`
- `subjectOutcomeSummaries`

## AP4 Fields

`warnings` remains for backward compatibility.

`excluded` is the structured explanation list for missing, incomplete, or excluded academic data. Each item should have:

- `reasonCode`
- `message`

Items may also include ids when safely available:

- `academicYearId`
- `semesterId`
- `subjectId`
- `sectionId`
- `assessmentId`
- `enrollmentId`
- `studentMembershipId`

Frontend should treat `reasonCode` as the stable display/branching key and `message` as short display text.

## Reason Codes Covered

School:

- `missing_assessment_result`
- `incomplete_school_year_outcome`
- `missing_semester_result`

University:

- `section_not_closed`
- `assessment_not_published`
- `missing_assessment_result`
- `invalid_assessment_configuration`
- `incomplete_assessment_weight_total`
- `invalid_credit_hours`
- `missing_academic_policy`

## Automatic Checks

These checks run directly against normal profile responses:

- login saves `adminToken` and `studentToken`
- shared profile response has `academicProfile`
- school profile has `institutionType: "school"`
- university profile has `institutionType: "university"`
- `warnings` is an array
- `excluded` is an array
- school profile requires `academicYearId`
- university profile works without `academicYearId`
- missing token returns `401`
- invalid ObjectId returns `400`
- student cannot use the staff target route
- finalOutcome summary is sanitized when present

## Data-Dependent Checks

These checks require fixture data. Leave the corresponding environment flag as `false` unless you intentionally prepared that case:

- `expectSchoolMissingAssessmentResult`
- `expectSectionNotClosed`
- `expectAssessmentNotPublished`
- `expectMissingAssessmentResult`
- `expectInvalidAssessmentConfiguration`
- `expectIncompleteAssessmentWeightTotal`
- `expectInvalidCreditHours`
- `expectMissingAcademicPolicy`
- `expectRepeatedAttempts`

When a flag is `true`, the matching Postman request asserts that the returned `excluded` or summary data contains the expected condition.

## Practical Fixture Tips

School incomplete result:

- Use a school student with an active class assignment for the academic year policy semesters.
- Ensure at least one published school assessment is missing the student's score.
- The profile should keep `warnings` and add `excluded` entries.

School final outcome:

- Run `Finalize School Year Outcome`.
- Run `School Profile After Finalization - Sanitized finalOutcome`.
- Verify no tenant ids, actor ids, audit fields, raw DB docs, or policy snapshots appear inside `academicProfile.finalOutcome`.

University open section:

- Enroll the target student in a non-closed section.
- Set `expectSectionNotClosed=true`.
- The profile should include `section_not_closed` and official GPA should not count that section.

University missing result:

- Use a closed section with published assessment weight total of `100`.
- Leave one target-student assessment result score missing/null.
- Set `expectMissingAssessmentResult=true`.

University incomplete weight:

- Use a closed section with published assessments whose total weight is not `100`.
- Set `expectIncompleteAssessmentWeightTotal=true`.

University missing policy:

- Use a closed, otherwise-finalized section in a semester with no resolvable active/archived university academic policy.
- Set `expectMissingAcademicPolicy=true`.

## Access Notes

- Self route: `GET /institutions/:institutionId/students/me/academic-profile`
- Staff route: `GET /institutions/:institutionId/students/:studentMembershipId/academic-profile`
- Staff target route currently requires `membership.manage` at the route layer.
- School provider also checks the existing `class.manage` pattern.
- University provider checks the current `section.manage` pattern.
- `accessMode` is internal service state only. It is not a public query parameter and should not be exposed to the frontend.
